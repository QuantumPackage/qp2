Character tables of the point groups
====================================

One file per point group, read by the ``symmetry`` module
(``src/symmetry/chartab.irp.f``). The file name **is** the group name: the
detector identifies a group by its measured invariants, builds a name, and
opens ``$QP_ROOT/data/Symmetry/<name>``. There is no override: the directory
is the one of the installation that runs the code, and ``QP_ROOT`` must be set
when the module is loaded.

Provenance
==========

These files were generated by the author of the symmetry module
(A. Scemama) on 2026-11-02 as part of developing it. They are original data:
they are **not** copied from a printed character-table compilation, so no
third-party copyright applies and they are distributed with Quantum Package
under the licence of this repository.

The generating script was not kept for the finite groups. The set is therefore
*fixed data*: it is extended by adding a file, never by regenerating the whole
directory. The two linear-molecule tables are the exception: their
construction is written out under "Linear molecules" below, and they were
regenerated from it. Every table is validated before it is used -- syntax when
it is opened, semantics against the enumerated group right after -- so a bad
file is rejected with a message instead of being used silently (see
"Validation" below).

Format
======

Tabs separate the fields; the notation below is exact (``\t`` is a tab).

1. ``Group\t<name>`` -- informational only: the detector takes the group name
   from the *file name* and never reads this line.
2. ``n\t<n>`` -- ``n`` is the number of irreps, which equals the number of
   classes. It is **not** the order of the group: ``D6h`` has ``n = 12``
   irreps and order 24.
3. A blank line.
4. A header line containing both ``Irred`` and ``Operation``.
5. ``n`` lines: ``<i>\t<irrep name>\t<operation symbol>``, with
   ``i = 1..n`` in order. The name is what the user sees (``A1``, ``B3u``,
   ``Sigma+``, ...), the symbol is a representative element of class ``i``.
6. Blank lines, then ``Table``.
7. A column-index line of ``n`` integers (present, skipped).
8. ``n`` lines of ``n`` numbers, read list-directed (free format), each
   preceded by its row index: row ``i`` is the row of irrep ``i``, in the
   order of step 5, and gives its character on each class, in the order of
   step 5. The shipped set is written in ``F10.5``; the two linear tables are
   the exception and carry 10 decimals (see "Linear molecules" below).

A worked example, ``C2v``::

    Group	C2v 
    n	4

         	Irred     	Operation
       1 	 A1         	 E         
       2 	 A2         	 C2        
       3 	 B1         	 sv        
       4 	 B2         	 sd        

    Table
             1         2         3         4      
       1   1.00000   1.00000   1.00000   1.00000  
       2   1.00000   1.00000  -1.00000  -1.00000  
       3   1.00000  -1.00000   1.00000  -1.00000  
       4   1.00000  -1.00000  -1.00000   1.00000  

The column of a class is found by **parsing its symbol**, not by its
position, so a table may list the classes in any order as long as the
symbols are the ones the detector emits: ``E``, ``Cn``, ``Cn^k``, ``S n``,
``i``, ``sv`` (plane ``xz``, normal ``y``), ``sd`` and ``s`` (plane ``yz``,
normal ``x``; ``sd`` is the other vertical class when ``sv`` is taken),
``sh`` (plane ``xy``, normal ``z``), ``C2'`` (the class through ``x``),
``C2"`` (the remaining one). When a group has a single vertical reflection
class, ``s``/``sv``/``sd`` all select it: only two or more classes force the
symbol to be resolved.

Validation
==========

``chartab.irp.f`` checks the syntax while reading: the two header lines, the
blank line, the ``Irred``/``Operation`` header, the ``i = 1..n`` sequence,
the ``Table`` marker, the ``n x n`` shape, and that nothing but blanks
follows the last row.

The content is then checked against the **enumerated** group, not against
itself (``columns.irp.f``): every class must match exactly one column symbol,
the characters must satisfy $\sum_c |c|\,\chi_a(c)\chi_b(c) = |G|\,m_a\,
\delta_{ab}$, the dimensions must satisfy $\sum_a d_a^2/m_a = |G|$, and they
must be multiplicative over direct products. A table failing one of these is
reported with the relation that failed and the run continues without symmetry
labels instead of aborting. ``|c|`` is the number of elements of the class,
``d_a = chi_a(E)`` and ``m_a`` is 2 when the table row is the sum of a
complex-conjugate pair of irreps (``C3``, ``C10``, ...) and 1 otherwise; that
is why the ``E`` irrep of ``C3`` enters as ``d^2/m = 4/2``.

Linear molecules: ``Cinfv`` and ``Dinfh``
=========================================

A collinear molecule is detected by ``pg_is_linear`` and its group is built
analytically from the canonical frame (``pg_build_linear``), not by the
permutation search used for the other groups: for a collinear geometry every
``sigma_v`` plane maps each nucleus to itself, and so does ``sigma_h`` when
there is a centre of symmetry, so the ``(perm, det)`` key that identifies an
element collapses -- the 31 planes and the horizontal one would all be one
element. The model is ``C31v`` (62 elements, 17 classes) or
``C31v x {E, sh}`` (124, 34); the detector renames the model to the chemical
name before opening the file, which is why the file is called ``Dinfh`` while
its body is the 34-class table. 31 is the largest order ``pg_proper_scan``
samples for a linear molecule; the matrices are exact rotations by
$2\pi k/31$ and the rows below are exact characters, so the sampled group is
handled exactly. The rotations of the continuous axis that are not sampled
act as the identity on a ``Sigma`` state and as a rotation inside a
two-dimensional irrep, i.e. they mix a degenerate pair only. The one thing
the model cannot resolve is a state of angular momentum $|\Lambda| \ge 16$,
whose restriction coincides with $|\Lambda| = 15$; no basis set reaches that
angular momentum.

``Dinfh`` is modelled as ``C31v x {E, sh}``, not as ``C31v x Ci``. Both are
valid 34-class models, but with the inversion the improper elements are
$i\,C_{31}^k = S_{62}^{31+2k}$ ($i$ is $S_{62}^{31}$): the 15 columns would
be named ``S62^33`` ... ``S62^61``, which no character table uses, and
``S62^31`` is rejected by the parser as an unreduced symbol (``i`` would have
to be written ``i``). The horizontal plane keeps the standard ``sh`` and
$S_{31}^k$. The model then has no inversion, and that costs nothing: with
$i = sh\,C_2(z)$ and $\chi(C_2(z),E_m) = 2(-1)^m$,

$$\chi(sh, E_m, g) = 2(-1)^m \qquad \chi(sh, E_m, u) = -2(-1)^m$$

so the rows are the restrictions of the ``Dinfh`` irreps to the model group
and the labels are the exact chemical ones (``Sigma_g+``, ``Sigma_g-``,
``Pi_g``, ``Pi_u``, ...). A ``Sigma`` row has no $C_2(z)$ factor to combine
and ``g`` there is simply $\chi(sh) = +1$.

Both files follow from these formulas, with $k = 1..15$ and $m = 1..15$; each
entry is the character of one element of the class (a merged
complex-conjugate pair counts as one column of 2 elements).
``Cinfv`` has the columns ``E, C31, C31^2, ..., C31^15, sv`` of length
``1, 2 (x15), 31``::

    Sigma+    1,   1 ...,   1
    Sigma-    1,   1 ...,  -1
    E_m       2,   2 cos(2 pi m k / 31) ...,   0

``Dinfh`` has the columns ``E, C31, ..., C31^15, sh, S31, ..., S31^15, C2',
sv`` of length ``1, 2 (x15), 1, 2 (x15), 31, 31``::

    Sigma_g+   1,  1 ...,  +1,  1 ...,  +1, +1
    Sigma_g-   1,  1 ...,  +1,  1 ...,  -1, -1
    Sigma_u+   1,  1 ...,  -1, -1 ...,  -1, +1
    Sigma_u-   1,  1 ...,  -1, -1 ...,  +1, -1
    E_m g      2,  2 cos(2 pi m k / 31) ...,  +2(-1)^m,  2(-1)^m cos(2 pi m k / 31) ...,  0, 0
    E_m u      2,  2 cos(2 pi m k / 31) ...,  -2(-1)^m, -2(-1)^m cos(2 pi m k / 31) ...,  0, 0

For a one-dimensional row $\chi(C2') = \chi(sh)\chi(sv)$, because
$C2' = sh\,sv$; it is 0 for the two-dimensional rows. Row 1 is
``Sigma_g+`` (all ones), the ``g`` block comes first, and
$\sum_a d_a^2 = 4 + 30 \times 4 = 124$ fixes the normalisation.

The bodies carry **10 decimals**, unlike the ``F10.5`` of the rest of the
directory. The characters of the ``E_m`` rows are irrational, and at 5
decimals the truncation is $5\times10^{-6}$: the projectors are then
orthonormal only to $\sim10^{-5}$, which is above ``pg_thresh = 1e-6``. The
MO gates read that as $tr P^a$ not integer, a diagonal element outside
$[0,1]$, and a non-idempotent projector -- they reject a perfectly
symmetry-adapted MO set. At 10 decimals the defect is $2\times10^{-11}$. The
same truncation affects every table whose two-dimensional characters are not
integers (``C5v``, ``C7v``, ``D5h``, ...); those files are still at 5
decimals and would need the same treatment before the gates mean anything
for them.

Files present but never selected
================================

``C1h``, ``C1v``, ``D1``, ``D1d`` and ``D1h`` are the ``n = 1`` cases where
two standard names collapse onto one group. The naming tree produces the
surviving name (``Cs``, ``Cs``, ``C2``, ``C2h``, ``C2v``), so these five files
are never opened.
